# Zoo de Lecture — mémoire du projet (à lire en premier)

## 1. Objectif
Appli web de fluence de lecture pour des classes de CP, en ligne sur https://zoodelecture.fr
- **Élève** (eleve.html → zoo-connecte.html) : lecture d'1 minute par son et par niveau (syllabes, mots, texte), en entraînement ou évaluation ; exercice d'écoute « J'écoute » ; animaux qui éclosent et grandissent ; pièces, roue, 8 jeux, boutique.
- **Enseignant / admin** (enseignants.html) : classes, élèves, suivi, réglages pédagogiques.
- **Guides pédagogiques** : `guides/<nom>/index.html` + `guides/guides.css` (mode d'emploi : `guides/README.md`) ; 5 publiés : `ateliers-lecture-cp`, `syllabes-lecture-cp`, `tablettes-lecture-cp`, `fluence-lecture-cp`, `differenciation-lecture-cp` (textes relus par Gabriel : à modifier avec son accord). **Partage** : `share.js` (landing, guides, espace enseignant). `sitemap.xml` + `robots.txt` ; aucune mesure d'audience (décision).
- **Landing page** (index.html) : présente le site, accès élève/enseignant/démo ; **démo sans compte** avec visite guidée.
- L'utilisateur (Gabriel, enseignant de CP) **n'est pas technique** : faire les manipulations soi-même.

## 2. Stack
- Site **statique** HTML/CSS/JS, sans framework, **un fichier par page**. Style : JS compact à l'ancienne (`var`, `function`, petits `el()`, `$()`, `nb()`, `q()`), commentaires en français, thème sombre pour les pages de connexion/landing, polices Fredoka + Figtree, variables CSS (`--ink`, `--muted`, `--line`, `--card`). Points de rupture téléphone : 600 et 880 px.
- Bibliothèque **supabase-js 2.118.0 copiée dans `vendor/supabase.js`** (fichier `dist/umd/supabase.js` de la version, chargé localement par eleve.html, contact.html, enseignants.html, zoo-connecte.html et tools/build_test_pages.py : plus de CDN). Pour changer de version : télécharger `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@X.Y.Z/dist/umd/supabase.js` dans `vendor/`, augmenter `?v=` dans les 5 fichiers, retester connexions élève/enseignant et contact.
- Hébergement **GitHub Pages**, dépôt public GMASSOT31/fluence-cp, branche `main`, domaine OVH (fichier `CNAME`). Mise en ligne **1 à 5 min** après une fusion.
- Backend **Supabase** (projet `pcxpazpflnlwmhyuozdx`, région Paris ; nom « Zoo de Lecture »). **Avant toute migration, vérifier avec `list_projects` que le connecteur Supabase voit bien ce projet** (il a déjà été relié à un autre compte avec un projet « CRM C2e » : ne rien y appliquer). Fonctions RPC `SECURITY DEFINER` avec `search_path=''`, règles RLS. La clé « publishable » dans le code est normale ; **aucune autre clé dans le dépôt**.

## 6. Décisions prises (ne pas remettre en question)
- **Pièces des jeux** : 1 (objectif atteint), 3 (record perso battu), 10 (record de la classe pris à un camarade) ; jamais additionnées, seule la plus haute compte ; **calculées par le serveur** (anti-triche).
- **Étoiles, médailles, verrou (décidé le 28/10/2026)** : **⭐ étoile = niveau (syllabes / mots / texte) réussi en entraînement ; 🏅 médaille = niveau réussi en évaluation avec l'enseignant**. Les deux sont **indépendants** : une médaille ne compte JAMAIS comme une étoile (une étape peut avoir les deux, jamais « 4 étoiles » pour 3 niveaux). **Le son suivant s'ouvre seulement si au moins un niveau du son précédent est certifié 🏅 en évaluation** (un entraînement seul ne suffit pas, réglage `lock`) ; un son où l'élève a déjà un résultat (entraînement ou évaluation) reste ouvert. **Niveau N de l'élève = rang de l'étape certifiée 🏅 la plus haute** (les entraînements n'y comptent pas). Code : `isTrained` (étoile), `isValid` (médaille), `soundCertified`, `isUnlocked`, `readLevel`, `evalWaiting` dans zoo-connecte.html ; `isPassed` (l'un ou l'autre) ne sert qu'à choisir « quoi faire ensuite ». Quand tout est entraîné mais pas évalué : « évaluation à prévoir avec ton enseignant ».
- **Voyelles en deux étapes (03/11/2026)** : son `voy` (a e i o u y) puis son `voy2` « é et è » (syllabes seulement). Réglages enseignant enregistrés avant : `withVoy2()` ajoute `voy2` après `voy` (zoo-connecte.html et enseignants.html). Élèves qui avaient réussi `voy` : `voy2Fix()` recopie leurs résultats réussis et leur écoute validée vers `voy2` (calcul fait à l'affichage des deux côtés, aucune migration SQL).
- **Deux parcours : vert = écoute, bleu = lecture (décidé le 06/11/2026, Zoo de Lecture seulement ; le Zoo de Calcul a ses 3 parcours : **ÉCOUTER violet, Addition orange, Soustraction rose**, mêmes variables CSS, `body[data-path]`, `setPath` dans labo-calcul.html ; les menus de droite du Calcul gardent encore leurs anciennes couleurs)**. L'élève voit `J'écoute` (vert) et `Je m'entraîne` (bleu), les deux qui pulsent à l'ouverture ; dès qu'il entre dans la lecture (`show` : lecture/cartes) la classe `body.path-read` passe tout en bleu (variables CSS `--go1/--go2/--go-bd/--go-glow/--go-pale`, `setPath`/`resetPath`) ; écoute/reconnues le remettent en vert. À l'accueil le parcours en cours passe en premier et pulse, l'autre est calme (`go-calm`). Le texte ci-dessous parle du vert : c'est la couleur du parcours en cours.
- **Étape suggérée = toujours verte (ou bleue en lecture) et qui pulse** (classe `.go-next`, cartes `.suggested` avec badge « 👉 Pour toi », bouton « 👉 Mon étape suivante » sur les écrans cartes/boutique/jeux/progrès ; `homeIfStudent()` ramène à l'accueil après une lecture). Un seul vert pulsant par écran : ne pas réutiliser cette couleur pour autre chose. **Même règle dans le Zoo de Calcul** (`labo-calcul.html`, PR 221) : `.go-next` sur « Je m'entraîne » (ou la roue), bilan, éclosion, roue, carte `.suggested` « 👉 Pour toi », `addNextBar(v)` sur cartes/reconnues/progrès/boutique/jeux.
- **Voix qui épelle une syllabe** (ex. « lo » lu « L O ») : ajouter un équivalent à `SYL_SAY_FIX` dans zoo-connecte.html (`lo: "l’eau"`) ; aucun fichier audio dans `sons/`.
- Entraînement < 15 s : n'est pas validé et n'entre ni dans les records ni dans la courbe (règle des 15 s plutôt qu'une confirmation).
- Un son réussi à l'écoute donne un tour de roue + la scène d'évolution ; scène d'évolution aussi **en attente** quand l'enseignant note plus tard une lecture enregistrée (`data.evos`, jouée à l'accueil).
- Démo : activée **uniquement** par `?demo`, n'envoie rien à Supabase, « Recommencer » revient à l'accueil du Zoo de Léo.
- Ordre des sons par défaut = progression PIANO CP (citable, aucun contenu du commerce copié). **Enregistrements audio des élèves : restent sur leur appareil.**
- PIN par défaut 1234 ; nouveau compte enseignant = 3 élèves (plus sur demande) ; ghost/suppression de classes ; l'admin peut renommer et changer le code des classes des autres (`admin_edit_class`).
- Écartés : pièces cumulées ; PIN aléatoires ; « Copier le lien élève » ; e-mails Supabase personnalisés (« rien pour l'instant ») ; jeu « Attrape-les » (remplacé par le Serpent) ; jeu « Compte les animaux » (remplacé par l'oiseau). Ancien `catch` et `count` restent acceptés par le serveur.
